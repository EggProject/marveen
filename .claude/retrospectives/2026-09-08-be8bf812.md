## Proposals

### 1. Vacuous-test check is a verifier-prompt requirement, not just a CLAUDE.md rule

- **type**: `update-skill`
- **target path**: `.claude/skills/refactor-cycle/SKILL.md`
- **rationale**: The vacuous-test pattern has now hit TWICE (2026-08-30
  E.1/E.2 + 2026-09-08 F.4 T6). The CLAUDE.md §8 rule about "megbukna-e
  ez az assertion, ha az implementációt konstans visszatérésre vagy
  no-opra kibeleznénk" exists and is correct, but it lives in a 250+
  line doc and did not get applied during the F.4 cycle's planning
  phase. Both verifier subagents (structural + adversarial) missed the
  vacuous assertion. Only the user-typed `/code-review max --fix`
  caught it. The fix is to make the vacuous-test check a MANDATORY
  step in the verifier subagent prompts emitted by the refactor-cycle
  skill — not a free-text CLAUDE.md rule that the implementer can
  paraphrase away.

  Concretely, add to `refactor-cycle/SKILL.md` (in the Phase 2
  "verification" section, after the structural-vs-adversarial split
  rule):

  > ### Verifier mandate: vacuous-test check
  >
  > BOTH verifier subagents (structural checklist AND adversarial
  > falsification) MUST include a per-`it()` audit that asks, for every
  > new assertion: "would this assertion fail if the implementation
  > under test were gutted to a no-op (constant return, ignored arg,
  > early-return undefined)?" A test that passes against a no-op
  > implementation is vacuous. Report any vacuous test as a HIGH
  > finding, even if the test is otherwise structurally sound.
  >
  > Precedents:
  > - 2026-08-30 E.1/E.2 (`process-lock.ts:102` `filterOwnNodeCandidates`,
  >   `getProcessCommand: () => null` fixture).
  > - 2026-09-08 F.4 T6 (`getOverrides()` spread assertion,
  >   `setOverride` rebinds `this.cache`).

  The `update-skill` routing is correct because the failure mode is
  verifier-prompt design, which the refactor-cycle skill owns (the
  workflow-authoring skill is global and the workflow scripts are
  per-cycle; the per-cycle verifier prompt lives in the cycle skill).
  Honcho memory already records the F.4 T6 lesson under the
  `f4-settings-store-code-review-skipped-findings` topic, so the
  corpus-traceable signal is there for grep retrieval, but the prompt
  template change is what prevents the third occurrence.
