## Proposals

### 1. Never hand the user a working directory outside the project root

- **type**: `claude-md`
- **target path**: `.claude/CLAUDE.md` (section 8, appended to the existing
  `/code-review` bullet)
- **rationale**: The existing bullet says only "dokumentáld a usernek, hogy
  neki kell indítania". It does not say from where, and it does not say what
  state the branch must be in first. Following it literally produced two
  escalating user corrections in one session: the user was sent to
  `$HOME/claw-test-e4`, outside the project directory, and asked to merge and
  copy the agent's own unfinished handoff. The correct sequencing is
  mechanical and cheap, so the rule should carry it.
- **proposed content** (append to the `/code-review` bullet in §8):

```markdown
  **A userre bízott lépés MINDIG a project mappában fut, és semmi más nem
  tartozik hozzá.** Mielőtt `/code-review max --fix`-et kérsz a usertől: a
  worktree-ben készült commit MÁR legyen visszavezetve a branch-re
  (`git merge --ff-only`), a munkás worktree MÁR legyen törölve, a gate-ek
  MÁR legyenek lefuttatva a FŐ mappában. A user kizárólag annyit kap, hogy
  `/code-review max --fix`, semmilyen `cd`, `git merge`, másolás vagy
  előkészítő lépés nem hárítható rá. Soha ne utasítsd a usert a project
  mappán kívüli útvonalra. Precedens: 2026-09-03 E.4 -- a jelentés
  "`cd $HOME/claw-test-e4` majd `/code-review max --fix`" formában ment ki,
  amire a user kétszer, egyre élesebben javított ("kilepsz a project
  mappabol", majd "utasitgattal hogy masolgassak meg merge-jek meg lepjek at
```

### 2. Ancestry check with `--is-ancestor`, not SHA equality

- **type**: `claude-md`
- **target path**: `.claude/CLAUDE.md` (section 8, the "Worktree-isolált
  commit visszavezetése a branch-re" bullet)
- **rationale**: The bullet currently prescribes
  "ellenőrizd: `git merge-base <branch> <SHA>` kell egyezzen a branch
  HEAD-del". That output is direction-ambiguous to read back, and this
  session read it in both directions within 20 transcript entries: correctly
  for `b453b58`, incorrectly for `5bcfcfa` (concluding "külön ágon van" for a
  commit that is in fact a descendant of the branch head). The wrong reading
  fed a `--force` deletion attempt on a worktree holding unmerged work.
  `git merge-base --is-ancestor A B` answers with an exit code and cannot be
  read backwards.
- **proposed diff** (replace the parenthetical in the existing bullet):

```diff
-Helyette `git merge --ff-only <SHA>`, ha a commit a branch gyermeke
-(ellenőrizd: `git merge-base <branch> <SHA>` kell egyezzen a branch HEAD-del).
+Helyette `git merge --ff-only <SHA>`, ha a commit a branch gyermeke. Az
+ellenőrzés `git merge-base --is-ancestor <branch> <SHA>`, exit 0 = a branch
+HEAD őse a commitnak, tehát a ff-merge lehetséges; exit 1 = NEM. NE a
+`git merge-base <branch> <SHA>` kiírt SHA-ját hasonlítgasd a branch HEAD-hez:
+az output ugyanúgy néz ki mindkét ancestry-irányban, csak a jelentése
+fordul meg, és visszafelé olvasva pont az ellenkezőjét állítja. Precedens:
+2026-09-03 -- a `git merge-base feature-develop 5bcfcfa` a feature-develop
+HEAD-jét adta vissza, amit az agent "az 5bcfcfa külön ágon van"-ként
+olvasott, holott az 5bcfcfa a branch LESZÁRMAZOTTJA volt (unmerged munka),
+és erre alapozva próbálta `--force`-szal törölni a worktree-t.
```

### 4. Retrospective reader must collect enqueued user messages

- **type**: `update-skill`
- **target path**: `.claude/skills/retrospective/scripts/transcript-report.ts`
- **rationale**: A user message typed while the agent is mid-turn is stored as
  a `queue-operation` entry with a top-level `content` string and no `message`
  field, so `buildReport`'s `if (!isRecord(message)) continue;` drops it. In
  this session that is exactly where the sharpest correction lived, and the
  reader reported `USER PROMPTS (3)` with it missing. A retrospective run that
  trusted the reader alone would have found nothing to propose here. Routing
  the enqueued content through the existing `collectUserText` is enough: its
  `MACHINE_TEXT_MARKERS` filter (`<task-notification>`, `<local-command`)
  already drops the six enqueued task notifications in this transcript and
  keeps the one real message. Filtering on `operation === "enqueue"` avoids
  the duplicate `remove` and `attachment` copies of the same text.
- **proposed diff** (in `buildReport`, before the `const message` lookup):

```diff
     if (parsed["isMeta"] === true) {
       continue;
     }
+    // A prompt the user typed mid-turn is stored as a queue-operation entry
+    // with a top-level `content` string and no `message` record, so the
+    // guard below would drop it. These are often the sharpest corrections of
+    // a session. Only "enqueue" is read: the matching "remove" entry and the
+    // `queued_command` attachment repeat the same text.
+    if (
+      parsed["type"] === "queue-operation" &&
+      parsed["operation"] === "enqueue" &&
+      isString(parsed["content"])
+    ) {
+      collectUserText(parsed["content"], collector);
+      continue;
+    }
     const message = parsed["message"];
     if (!isRecord(message)) {
       continue;
     }
```
