## Proposals

### 1. Add a "file line numbers banned in persistent text" rule to CLAUDE.md §7

**type**: claude-md
**target path**: `.claude/CLAUDE.md`
**rationale**: Second corpus hit of the "references in persistent
text that go stale" family. The fdae5062 retrospective (just
before this session) added a ban on iteration/cycle/attempt
markers (`cycle 2`, `attempt N`, `H.4 phase 2`) in comments,
tests, and commit messages. The current user complaint extends
the same family to `L<n>` / `<file>:<n>` line numbers, with the
same reasoning: "mert ha megvaltozik senki nem fogja javitani!"
The existing CLAUDE.md §7 rule "MD és commit message hivatkozások
ellenőrzése commit ELŐTT" sub-bullet (1) says file:line references
must be verified at commit time. The user is saying verification is
insufficient — the reference goes stale at the NEXT commit and
nobody updates it. The fix is to ban the reference type outright
and use symbol/section names instead.

Proposed addition (insert into §7 next to the existing
iteration/cycle ban, as a new bullet in the same "references that
go stale" family):

```
- **Fájl sorszám-hivatkozások (`L<szám>`, `<fájl>:<sor>`) TILOSAK
  MD-kben, tervekben, refactor-tervekben, commit message-ekben és
  kód kommentekben.** Helyette function nevet, típusnevet vagy
  komment-szakasz címét használj (pl. `// --- Pending Channel
  Requests ---` szakaszcím, `upsertChannelRequest` symbol-név,
  `§A13` szekció-azonosító). A sorszámok commitokkal elcsúsznak
  és senki nem frissíti őket — a user 2026-09-12-en szóban
  jelezte: „fajl sorszamot commentbe ne irjal, mert ha
  megvaltozik senki nem fogja javitani!" (a ba3ea6e2 session
  tervét ezért kellett újraírni `L1592–1631` / `L1503–1514`
  stílusú referenciák nélkül). A `docs/needs-to-be-fix/`,
  `docs/refactor-to-classbase/`, plan MD-k és shared-memory
  bejegyzések mind érintettek. KIVÉTEL: a `cat -n` style
  inline idézet, ahol a sorszám az idézet RÉSZE (nem
  referencia), engedélyezett.
```

This rule goes in §7 next to the existing iteration/cycle ban
because it is the same family ("references in persistent text
that will go stale"). It replaces the "verify before commit"
intent of the existing sub-bullet (1) with a ban, mirroring how
sub-bullet (4) (SHA) is already a ban.

If applied, the change should also either:
- (a) Delete the existing §7 sub-bullet (1) `file:line -- Read-eld
  a forrást a hivatkozott sorokon` from the "MD és commit message
  hivatkozások ellenőrzése commit ELŐTT" rule (because the new ban
  supersedes it), or
- (b) Rephrase it to: `(1) \`file:line\` -- BANNED, see the
  file line number ban above` (to keep the four-alfaj structure
  intact as a teaching artifact).

Recommendation: (b) — keep the four-alfaj structure for future
readers who scan the rule, but mark (1) as superseded.

A follow-up commit on `refactor/classbase` should also re-audit
the existing `docs/needs-to-be-fix/` and `docs/refactor-to-
classbase/` MD-k for `L<n>` style references and rewrite them to
symbol/section names. The 2026-09-12 fdae5062 retrospective's
"Not proposed" section noted that the `needs-to-be-fix` MD system
had 87 MD-touched commits with stale references (`e399a96` etc.) —
the same anti-pattern, just not yet banned. The new rule would
prevent FUTURE stale references but not retroactively fix existing
ones; a separate docs-audit commit is needed for that.
