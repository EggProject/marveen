## Proposals

### 1. Add an "iteration/cycle marker" rule to CLAUDE.md §7

**type**: claude-md
**target path**: `.claude/CLAUDE.md`
**rationale**: User emphatic correction with `millioszor` marker
(recurring problem across sessions). The existing §7 bullet covers
SHAs and pre-state file:line refs, but does NOT cover
cycle/iteration/attempt markers. The user's exact complaint was
about `H.4 cycle 2` — a counter, not a SHA. Without a rule, future
sessions will repeat this mistake.

Proposed addition (insert into §7 after the existing SHA/inline-SHA
bullets, as a new bullet in the same "references that go stale"
family):

```
- **Iteráció/cycle/attempt markerek TILOSAK kód kommentekben,
  teszt nevekben és commit message-ekben.** Ne írj `cycle N`,
  `attempt N`, `H.4 phase 2`, `második nekifutás`, `retry #3`
  típusú jelölőket — ezek NÉMA aging: a `cycle 2` `cycle 5` lesz,
  és senki nem frissíti. A kód legyen önmagában érthető, a
  kontextust a commit message + a history adja. Precedens:
  2026-09-12 H.4 session (fdae5062) — a tervben `H.4 cycle 2`
  megjelent a header comment update szövegében, a teszt nevében
  (`(18): error subclass discriminators stay mutually exclusive
  (H.4 cycle 2)`) és a commit message subject-jében. A user
  szó szerint elutasította: "NEM JO!!! Elmondtam millioszor
  commentbe nem irunk hivatkozasokat mert azok meg fognak
  szunni! peldaul `H.4 cycle 2`!!!".
```

The rule goes in §7 next to the existing SHA/history-ref bullets
because it is the same family ("references in persistent text that
will go stale"). The `paths` frontmatter of the rule is irrelevant
here — this lives in CLAUDE.md, not a `paths`-scoped rule file.

If applied, the change should be a follow-up commit on
`refactor/classbase` with subject `docs(claude-md): ban cycle/
iteration markers in comments, tests, commit messages` and the
body referencing the fdae5062 session + the user's exact quote.
