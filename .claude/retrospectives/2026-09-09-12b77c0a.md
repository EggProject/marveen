### 1. CLAUDE.md §7: shared-memory file commit must happen immediately after Write, not "at session end"

- **type**: `claude-md`
- **target path**: `.claude/CLAUDE.md` §7 (extend the
  "Memory dual-write szabály" bullet's trailing text)
- **rationale**: Three corpus hits in 24h (2026-09-07 `1d029d91`
  end-of-session untracked, 2026-09-09 `ff2f88e4` mid-session after
  code-review, 2026-09-09 `12b77c0a` TWICE in one session -- once
  after Phase 5 capture, once after first code-review). The 2026-09-09
  `ff2f88e4` retro explicitly flagged this as a re-surface candidate:
  "If the same reminder comes up in the next refactor cycle,
  re-surface then." It did. The pattern's cost is ~3-5 min per
  occurrence (user interruption + state verification + author pre-check
  + commit) and the friction is that the existing `kötelező mindig
  commitolni` (§6) and the dual-write rule (§7) say WHAT to do but not
  WHEN. The agent defers the commit because the file "feels like
  session output" rather than code change. The fix is to add a
  cadence rule: the `Write <file>` call on a
  `.claude/shared-memory/*.md` path MUST be followed in the same
  turn by `git add <file> && git commit`, before any other tool call
  that touches the working tree (Bash with `git status`, Edit on
  anything else, etc.). This makes the commit deadline
  event-driven (the Write call) rather than session-driven (the
  end of the session). It does NOT conflict with the existing
  `pnpm claude:memory write <topic> <content-file>` script -- the
  script writes the file, then the agent commits per the new rule.

  Add to `.claude/CLAUDE.md` §7 (insert as a new bullet after the
  existing "Memory dual-write szabály" paragraph, since both rules
  govern the same shared-memory files):

  > - **A `.claude/shared-memory/<topic>.md` Write-ot azonnali
  >   `git add <file> && git commit` kövesse, ugyanabban a
  >   tool-körben.** A shared-memory file NEM "session output a
  >   session végére" -- az a `kötelező mindig commitolni` (§6)
  >   megsértése. A trigger a `Write` tool hívás: amint a fájl
  >   lemezre került, a következő tool-hívás `git add <file>
  >   && git commit -m "docs(shared-memory): add <topic>
  >   entry"` legyen, author pre-check-kel (§8), push nélkül
  >   (§6). Kivétel: ha a Honcho `create_conclusion` a
  >   shared-memory write ELŐTT vagy UTÁN nem futott le, a
  >   commit ELŐTT pótold a Honcho write-ot. Precedens: 2026-09-09
  >   `12b77c0a` session -- a `f-idea-store-db-client-flakiness.md`
  >   és a `f-idea-store-code-review-skipped-findings.md` is
  >   uncommitted maradt a Write + Honcho write után, a user
  >   `nem lett commitolva a memoria fajl!` prompttal szakította
